## 需求决议草案（原 TBD-01～06）

### TBD-01 算法参数（已决议草案）

- **UI**：本期 **不提供** 完整滤波参数表单（避免前后端与 Python 强耦合）。
- **参数来源**：滤波算法参数由 **Python 服务配置文件或环境变量** 维护；Java 任务仅携带 **输入 LAS 路径、输出路径、任务 ID** 等，不向 Python 传参数字典（除非后续增加「预设档位」枚举）。
- **校验**：路径存在性、扩展名、任务状态在 Java 与 Python 两侧分别校验；参数合法性以 Python 启动时校验为准。

**增补（2026-05）— 离线算法 CLI 已对齐本条「参数在 Python 侧生效」的工程现实**

- **仓库**：`python_filter/` 提供 `python -m python_filter` CLI，直接向进程传入 `method`（`sor`|`ror`）及 `k`/`std_ratio`（SOR）或 `radius`/`min_neighbors`（ROR），等价于配置文件级「显式旋钮」——满足毕设离线复现。
- **未来 REST**：`POST /jobs` 载荷建议在实现阶段镜像 CLI 关键字（仍以需求「UI 不报详细表单」为界：**浏览器不调参**，但 **编排层可下发固定或预设参数组**）。

### TBD-02 任务失败与重试（已决议草案）

- **调用方式**：Java 对 Python **REST** 采用 **提交作业 + 轮询状态**（首期无 Webhook）。
- **超时**：建立连接超时 **5s**；提交作业读超时 **60s**；单次状态查询读超时 **15s**。
- **重试**：仅对 **网络故障 / 5xx / 超时** 重试，**最多 3 次**，间隔 **1s / 2s / 4s**；**4xx** 业务错误 **不重试**。
- **死信**：不设独立消息死信队列；失败将任务记为 **FAILED**，**错误信息写入 PostgreSQL** 供前端展示。

### TBD-03 并发与配额（已决议草案）

- **全局并行**：同一时刻处于 **RUNNING** 的任务数上限默认为 **1**（单机毕设、降低资源争用）；可通过配置改为 **2**。
- **单用户**：不单独设 per-user 配额（与全局队列一致）。
- **排队**：超出并行上限的任务保持 **PENDING**，**FIFO** 出队；大文件（约 3GB）**不拆片**，依赖顺序执行与磁盘 IO。

### TBD-04 注册与账户（已决议草案）

- **不开放** 自助注册与邮件审批。
- **账号**：预置演示账号或通过 **运维/SQL** 插入（毕设环境）；维持 **单角色**（登录即可）。

### TBD-05 双窗口数据（已决议草案）

- **接口形态**：前端优先使用 **一次聚合**：`GET /api/tasks/{taskId}/comparison-bundle`（名称可随实现调整），响应包含 **原始 LAS / 滤波结果 / 预览** 的元数据及 **受控下载方式**（见安全节）。
- **预览**：Python 生成 **降采样预览**；浏览器侧加载 **单级 LOD**；默认预览点数上限 **500 000**（可配置）；交换格式优先 **PLY** 或与 Three.js 加载方案一致的格式（实现阶段在 `file-metadata` 定稿）。

### TBD-06 非功能（已决议草案）

- **性能**：不对「3GB 全量处理时长」作合同级 SLA；以实测与论文描述为准。
- **日志**：开发环境全量；生产/答辩环境建议保留 **30 天**（毕设可仅开发环境）。
- **密钥**：禁止写入仓库；使用 **环境变量** 或本地覆盖配置。
- **路径安全**：对象存储路径或磁盘绝对路径 **仅服务端可见**；浏览器仅通过 **鉴权后的 URL**（如短期签名或带 token 的下载接口）获取文件流。
- **大文件单机假设（增补 2026-05）**：`python_filter` 使用 `laspy` **分块解码**以降低读盘峰值内存，但 **SOR/ROR neighbour 检索需一次构建 KDTree**：当前 MVP 隐含 **解压后全部 XYZ 可乘入单机 RAM**（论文需声明该边界；超限任务走「瓦片滤波」为未来工作）。

## 已确认摘要（来自立项澄清，不变）

- **业务**：LAS 点云自动化滤波；Python 读大文件、执行算法、生成缩略预览；Java 负责鉴权、任务调度、PostgreSQL 业务数据与文件路径记录。
- **集成**：Python 为常驻服务；Java 通过 **REST HTTP** 下发/查询处理任务。

## 离线 LAS 滤波算法（已实现模块，独立于 Mock REST）

实现目录：`python_filter/`（requirements 见同名 `requirements.txt`）。

### 方法与数学（需求冻结）

| 令牌 | 库 / 数据结构 | 关键参数默认 | 说明 |
|------|---------------|--------------|------|
| `sor` | `scipy.spatial.cKDTree`；每个点与其它点的欧氏距离 | `k=20`，`std_ratio=1.0` | 对每点取其 **k** 最近邻距离均值 `mean_dist`，若 `mean_dist > global_mean + std_ratio * std` 剔除 |
| `ror` | `sklearn.neighbors.BallTree`；半径球查询 | `radius=1.0`，`min_neighbors=5` | 统计半径邻域内点对数；**不包含自身**：API 返回值减 1 后与阈值比较 |

### I/O

- **输入**：`.las`/`.laz`（LAS 语义优先 XYZ；其它 dimension 需在「subset 写入」路径保留）。
- **输出**：`.las`/`.laz`——**streaming subset**：沿源文件 chunked 读出，拷贝 `LasHeader`，仅写出保留索引对应 `ScaleAwarePointRecord`；可选 `.pcd` ——极简 ASCII XYZ 供工具链检视。

### 可观测度量

离线 stdout 对齐论文/前端指标：`timing_total_sec`、分段 `decode/filter/write`、`N_before`、`N_after`。字段键名应与 future REST `/jobs/{id}` 对齐（见 `2.design/server/python-gateway`）。
